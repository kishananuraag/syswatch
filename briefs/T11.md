# T11 — Analytics revamp: time-axis ladder, peak chips, power panel, overview IA

Read `docs/ui-analytics-plan.md` first — it is the design contract and the
research base (Shneiderman mantra, ONS axes manual, Almossawi time-series,
Datawrapper label rules). This brief implements it.

## Scope

Touch only `dashboard/` (server routes + static assets). Do NOT touch `src/`,
`Cargo.toml`, `briefs/`, `GOAL.md`, `LEDGER.jsonl`, `tools/`, `packaging/`.
No CDN, no framework, no build step.

## Work items, in order

1. **`tick_ladder` in `dashboard/server.py`.** `/api/graph` responses gain
   `"ticks": [{"ts": <epoch>, "label": "Mon 16"}, ...]` computed per the ladder
   table in the plan (1m→15s, 5m→1min, 15m→3min, 1h→10min, 6h→1h, 1d→3h,
   7d→calendar days, 30d→~5 calendar days, 1y→calendar months). Ticks sit on
   calendar boundaries for day/month ranges. 5–10 labels max. The frontend uses
   these labels verbatim — no more raw `p.ts` into Chart.js.
2. **Gaps are gaps.** Where points are missing, the series must carry `null`
   (Chart.js `spanGaps:false`) — never a fabricated zero.
3. **Peak chip.** Server computes per metric: max in window, its timestamp, and
   `is_spike = max >= median*1.2`. Response field `"peak": {"value":..,"ts":..,
   "is_spike":bool}`. Frontend renders `peak 87% · 14:32` or `steady`.
4. **Overview strip.** 6 KPI cards (CPU, memory pressure, GPU, network, disk,
   power), each: big value, sparkline, peak chip. Cards link to section pages.
   Shared time-range control on every card.
5. **Power panel** per plan tiers. New read-only endpoint `/api/power` returning:
   `battery_w` (V×A, unprivileged), `charging`, `by_app` (top 10 from the
   collector's `by_energy` — reuse, do not recompute), and
   `package: {cpu_w:null|value, gpu_w:null|value}` where null means "unavailable
   on this machine without root" — the UI must render `unavailable`, never 0.
6. **Section pages** for cpu/memory/gpu/disk/network/battery/apps matching the
   plan's layer-2 list, fed by existing endpoints plus `/api/power`.
   Battery page: %, time remaining, cycles, condition, health %, cells (if the
   collector exposes them; else `unavailable` + reason).

## Honesty rules

- A metric that does not exist renders `unavailable` with the reason. Zero is
  only for a real zero reading.
- Do not invent GPU/package watts. Null → "needs root / unavailable".
- Sensor names: `Sensor <n>` unless proven by value range, then "hypothesis".
