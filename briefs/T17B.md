# T17B — Apps redesign + Knowledge page + Power & battery analytics

Depends on T17A (bento L1 + L2 drawer + theme). Builds the three remaining
surfaces: the Apps view, the knowledge/manual page, and the Power & battery
section of Analytics.

## A. Apps view (purpose: "where did my machine's time, memory, disk, network
and energy go, by application, over this window?")

Ranged analysis view, NOT a live feed. Refreshes only on range change.

- Table: one row per app. Columns: name, avg CPU %, peak CPU %, memory MB,
  energy Wh, disk R/W MB, network MB, share of total. Per-app sparkline.
- Sort by any column (click header). Filter by name (input). Full scrollable
  list (virtualised, ~30 DOM rows + buffer) — no top-5 cap.
- Row click → L2 drawer for that app: its own series across the range
  (CPU, memory, energy, disk, network) + peak moments + coverage.
- Cross-module link: the per-module consumer lists (already built) are the
  module cut; Apps is the application cut. Same numbers, two views.
- No "gap to leader" — share of total only.
- Empty state: "no sweep in this range yet — the store sweeps every 20 s".

## B. Knowledge page (the "?" link in the topbar → /knowledge or a settings tab)

Manual-style. One card per metric. Each card:
  - Name (e.g. "CPU utilisation")
  - What it measures (one sentence)
  - Formula (if derived, e.g. attributed W = sum per-process energy)
  - Source (e.g. host_processor_info, IOAccelerator, root daemon sample.json)
  - Sampling cadence + retention tier
  - What a gap means (e.g. "null = no data in this window, not zero")
  - Link to the module's L2 drawer

Sections: CPU · Memory · GPU/ANE · Battery · Package power · Thermal ·
Network · Disk · Consumers · Coverage. Include the P/E cluster mapping rule
(efficiency cluster enumerated first on Apple Silicon) and the X-axis ladder.

## C. Power & battery analytics (Analytics view, "Power & battery" section)

Honest, measurable:
- Energy used (Wh) for the selected range, with per-app breakdown (already
  computed in /api/power). Stacked bar: top 5 apps + "other".
- Current draw (W), time-to-empty, charge-to-full, battery health %, cycle
  count, design/max capacity (from ioreg, cached 24 h).
- "Battery life at current draw" → X hours (capacity ÷ draw). Labelled
  *at current draw*.
- Degradation outlook: current health % + observed cycle rate (cycles/day
  from our own history) → linear projection to 80 % health. Shown ONLY
  with the caveat "estimate; assumes current usage pattern, not a
  prediction." If < 2 weeks of history, show "insufficient data" instead.
- Cost: tariff-gated (hidden until user enters a rate in settings). In the
  same section, not a separate tile.

Display per section: each module tile shows its energy contribution in Wh;
the Power section aggregates into total draw + battery impact.
