# T5 — Parity matrix and graphs fed by the real iStat corpus

## Goal
Two deliverables: (1) a **parity table** that states, metric by metric, where our number comes from and whether it matches iStat within a stated tolerance; (2) graphs in the dashboard that render **from the iStat fixture** — so the chart work can be built and tested without a live collector, and so every panel is provably reading the same shape we will produce ourselves.

## Inputs already on disk (do not regenerate)
- `fixtures/istat/manifest.json` — row counts, ranges, interval ladders, units
- `fixtures/istat/sample.jsonl` — 267 merged records, 90 s interval, 2026-11-15 08:13 → 15:19 IST
- `fixtures/istat/{cpu,load,memory,swap,gpu,network,diskactivity,battery,sensors}.jsonl`
- Verified facts from the exporter (use these, do not re-derive): CPU is % of **total** machine capacity (mean 23.4 % over that window); memory in MB; swap in GB; GPU %; network MB/s; disk KB/s; sensor keys are md5 hashes with **no names stored**.

## Do this
1. **`docs/parity.md`** — one row per metric:

   | Metric | iStat source (table.column) | syswatch source | Tolerance | Status |
   |---|---|---|---|---|
   | CPU total % | `cpu.user + cpu.system` | `cpu.total_pct` | ±3 % abs, same tick | PASS/FAIL/UNTESTED |
   | Load | `load.one` | `load.one` | ±0.05 | … |
   | Memory wired/app/compressed | `memory.*` | `memory.*` | ±64 MB | … |
   | Swap | `swap.swap` (GB) | `memory.swap_used` | ±0.05 GB | … |
   | GPU % | `gpu.processor` | `gpu.util_pct` | ±5 % abs | … |
   | Net rx/tx | `network.*` | `network[*].rx_bps` | ±10 % rel | … |
   | Disk R/W | `diskactivity.*` | `disk.rate` | ±15 % rel | … |
   | Per-proc CPU | **not stored by iStat** | `processes.by_cpu` | n/a — new capability | NEW |
   | Per-proc energy | **not stored by iStat** | `processes.by_energy` | n/a — new capability | NEW |
   | Temp / fan | `sensors.*` (unnamed keys) | TBD | — | UNTESTED |

   Every row states where the number comes from and whether a real comparison was run. `UNTESTED` is a legitimate value; a made-up green is not.
2. **Fixture replay mode** in `dashboard/server.py`: when `SYSWATCH_FIXTURE=fixtures/istat/sample.jsonl` is set, `/api/current` and a new `/api/graph?metric=<name>&from=<ts>&to=<ts>` serve **from the fixture** instead of a live collector, with the same JSON shape the live path emits. Live behaviour must be unchanged when the env var is absent.
3. **Graphs**: the frontend renders CPU (line, user+system stacked), memory (wired/app/compressed stacked area), network (two lines), disk (two lines), GPU (line). No CDN, no build step — vendored assets only, stdlib server. Clean typography, no chart junk: axis in IST, hover shows exact value, 200 ms transitions maximum.
4. **A parity checker**: `scripts/parity_check.py` reads `fixtures/istat/sample.jsonl` and the live `--json` snapshot, matches the nearest tick within 90 s, and prints the tolerance verdict per metric into `docs/parity.md`'s table format.

## Constraints
- Python stdlib for the server (psutil is acceptable, already used). No JS frameworks, no network fetches at runtime.
- Bind `127.0.0.1` only. Do not break `/api/health`, `/api/agent-events`, `/api/agent-stream`, `/api/current`.
- Do not touch `src/`, `Cargo.toml`, `GOAL.md`, `LEDGER.jsonl`, `tools/`, `briefs/`.
- Sensor keys stay unnamed — if you map one, prove it by value range and say it is a hypothesis, not a fact.
