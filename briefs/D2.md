# D2 — Dormant supervisor: plan-mode first, wake only on exception

## Goal
Extend `tools/driver.py` so it (a) runs every build task through **plan mode first**, and (b) never keeps a paid supervisor in the loop — it invokes Hermes **once, on an exception**, with a compact packet, and otherwise stays silent.

`tools/driver.py` already exists and passes D1. **Extend it; do not rewrite it.**

## Part A — plan mode before build (per task)
For tasks with `"kind": "build"`:
1. Run `opencode run --agent plan "$(cat briefs/<id>.md)"` → tee to `logs/<id>-<attempt>-plan.log`.
2. Save the agent's plan text to `.hermes/plans/<id>-agent-plan.md` (create dir if missing).
3. Then run the build dispatch exactly as today.
Add an optional per-task `"agent"` field (`"plan"` or `"build"`, default `"build"`); `kind == "light"` never gets a plan phase.

## Part B — the five wake triggers
A run wakes the supervisor **only** when one of these is true:
- `W1` a task reaches attempt 3 and still fails
- `W2` acceptance passed but `git diff --numstat` shows > 400 changed lines, or the diff touches any path listed in the task's `forbidden` array (default: `briefs/`, `GOAL.md`, `LEDGER.jsonl`, `src/`, `dashboard/` for driver tasks)
- `W3` two different tasks failed with the same first-error line (normalise whitespace)
- `W4` nothing runnable: every remaining task is `done`, `failed`, or blocked on an unmet dep
- `W5` a build task was thermal-deferred 10 times, or the wake budget is spent

Nothing else wakes it. Retries, model rotation, transient errors and slow tasks are logged and continue.

## Part C — how a wake happens (this is the token fix)
```
hermes -z "<packet>" --usage-file logs/wake-<ts>-usage.json
```
- Binary: `command -v hermes` → `/Users/barbarian/.hermes/hermes-agent/.hermes/bin/hermes` (verify at runtime; never hard-code an unverified path without a fallback).
- Packet ≤ **2048 bytes**, exact shape:
```
GOAL: <first non-heading line of GOAL.md>
TASK: <id> attempt <n>/3 kind=<kind> model=<model>
TRIGGER: W<n>
FAILING: <exact command>
EXIT: <code>
STDOUT_TAIL:
<last 40 lines, truncated to 1200 chars>
LEDGER:
<last 3 rows, one per line>
ASK: amend brief | amend acceptance | park | stop
```
- Timeout the wake at 180 s; a non-zero wake exit is logged as `wake_failed` and the driver **continues** (never blocks the queue on the supervisor).
- **Wake budget: 6 per 24 h.** On the 7th, park the task as `needs_human`, write `reports/NEEDS_HUMAN.md`, exit 3.

## Part D — dormancy is visible
Append `{"kind":"sleep","text":"idle: <reason>","ts":...}` to `.hermes/run/events.jsonl` whenever the driver has nothing to do (queue empty, all blocked, or `--max-minutes` expired). This makes "the supervisor was dormant" a fact in the log instead of a claim.

## Constraints
- Python **stdlib only**. Never `sudo`, never `git commit`, never `git push`, never edit `briefs/`, `GOAL.md`, `src/`, `dashboard/`.
- One agent process at a time. Hard-kill a task's process group at `--task-timeout` (default 45 min).
- All existing D1 behaviour (sequential, `--dry-run`, `--once`, `--max-minutes`, `--queue`, status persistence, ledger, events, `reports/<date>.md`) must keep working.
