# D1 — The queue driver (this is the machine that keeps working while I sleep)

## Goal
`tools/driver.py` runs a task queue unattended: one task at a time, acceptance-verified, retried on failure with model rotation, thermal-guarded, fully logged — so the loop keeps iterating when no human or paid supervisor is awake.

## Context
- `.hermes/queue.json` — `{"updated":..., "tasks":[{"id","brief","model","kind":"build|light","deps":[],"status"}]}`
- `briefs/<id>.md` — each task's brief, ending with an **Acceptance commands** block (shell commands, one per line in a fenced block after the `## Acceptance commands` heading).
- `LEDGER.jsonl` — append-only task ledger.
- `.hermes/run/events.jsonl` — append-only event stream the cockpit UI reads.
- `.hermes/model-roster.md` — the rotation ladder.
- `scripts/measure_collector.py` — measurement harness.

## Required behaviour
1. `python3 tools/driver.py [--once] [--dry-run] [--max-minutes N] [--jobs 1]`
   - With `--jobs 1` (only supported value for now): strictly sequential.
   - Respects `deps`: a task runs only when every dependency's `status == "done"`.
   - `--dry-run`: prints the resolved order and what would run; changes nothing, runs nothing.
   - `--max-minutes N`: stops cleanly after N minutes, leaving the queue intact for the next window.
2. **Execution per task**: `opencode run "$(cat briefs/<id>.md)" --model <model>` with a pty, output tee'd to `logs/<id>-<attempt>.log`. Capture exit code and wall time.
3. **Verification**: after the process exits, extract the acceptance commands from the brief and run each one; a task is `done` only if **every** command exits 0. Never trust the agent's prose.
4. **Retry ladder** (max 3 attempts):
   - attempt 1 fails -> re-dispatch the same model, appending the last 80 lines of its log under a `## Previous attempt failed with` heading
   - attempt 2 fails -> rotate to the next model from the roster ladder
   - attempt 3 fails -> mark `failed`, park it (`needs_review`), **continue with independent tasks** — never stall the queue
5. **Thermal guard** — refuse to start a task with `kind == "build"` when:
   - 1-minute load average > 50% of `os.cpu_count()`, or
   - `pmset -g therm` reports `CPU_Speed_Limit` < 80 (throttling)
   Wait 60s and re-check, up to 10 times, then park the task as `thermal_deferred`. Non-build tasks are never blocked by this.
6. **Every step appends an event** to `.hermes/run/events.jsonl`:
   `{"ts","job","kind":"dispatch|stdout|verify|retry|pass|fail|park|deferred","model","attempt","exit","duration_s","text"}`
   Text must be short (<= 500 chars); never dump whole logs.
7. **Report**: on exit, write `reports/<YYYY-MM-DD>.md` — table of tasks (id, model, attempts, verdict, duration), the failing acceptance command for each failure, and a `NEEDS REVIEW` section listing parked tasks with the log path.
8. Exit codes: `0` everything done, `3` some tasks failed/parked, `4` queue exhausted or nothing runnable.
9. Idempotent: re-running after a stop must not re-run tasks already marked `done` (status persisted in `queue.json`, plus a completion record in the ledger).

## Constraints
- Python **stdlib only** (pty via `pty`/`subprocess`; no pexpect, no rich).
- Never `git commit`, `git push`, `sudo`, or install anything.
- Never edit `briefs/`, `GOAL.md`, `src/`, `dashboard/` — the driver orchestrates, it does not develop.
- Cap concurrent agent processes at 1.
- Must survive a task that hangs: kill its process group after `--task-timeout` (default 45 min) and treat it as attempt failure.
