# T14D — P/E cluster render fix (supervisor screenshot evidence)

## Defect

On `/#cpu` the section headed `UTILISATION · P/E CLUSTERS` renders:

> unavailable
> now · host_processor_info · cores unknown

But the API returns exactly what is needed:

```
/api/current → cpu.clusters = [{index:0,name:"efficiency",cores:4},
                               {index:4,name:"performance",cores:4}]
             → cpu.per_core_pct = [68,65,66,58,3,2,1,1]   (8 values)
```

So the render path reads a field that does not exist (`cpu.cores`/topology) and
falls back to the unavailable branch. The cluster mapping and order are now
CORRECT (efficiency first at index 0, performance at index 4 — verified) —
only the UI wiring is broken.

## Fix

1. **Server**: add the aggregate to each cluster in `/api/current`:
   `util_pct` = mean of `per_core_pct[index .. index+cores-1]`, plus
   `freq_mhz` when known. Do not change names/order.
2. **Frontend**: render the P/E section from `cpu.clusters` + `cpu.per_core_pct`:
   one ring/bar per cluster with its `util_pct`, a label
   (`Performance · 4 cores`, `Efficiency · 4 cores`), and per-core ticks
   underneath. Only render the unavailable branch when `clusters` is missing,
   and say precisely which field was missing.
3. Also show cluster temperatures when the sensor registry has them
   (root-gated: plain `needs root` chip until then).
