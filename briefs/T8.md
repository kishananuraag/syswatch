# T8 — Durability: survives reboot and comes back by itself in under 60 s

## Goal
After a reboot and a login, syswatch is running again with no human action, and its own health is provable. One LaunchAgent for the app, one for the collector if they are separate processes, both unattended, both logged, both restartable.

## Required behaviour
1. **LaunchAgent plists** written to `~/Library/LaunchAgents/`, committed to the repo as templates under `packaging/launchd/` with `__HOME__` placeholders (never commit a machine-specific absolute path as the source of truth).
2. `RunAtLoad: true`, `KeepAlive: {"SuccessfulExit": false}`, `ThrottleInterval: 10`, `ProcessType: Background`, `StandardOutPath`/`StandardErrorPath` under `~/Library/Logs/syswatch/`.
3. The collector binds `127.0.0.1` only, port 8123, and the dashboard's single-instance guard must still prevent double-bind after a restart.
4. Restart robustness: kill -9 the app → launchd brings it back within 60 s (prove with timestamps in the log).
5. `scripts/install.sh` — one command, idempotent: writes the plists, `launchctl bootstrap`, verifies; `scripts/uninstall.sh` reverses it cleanly.
6. A verification command that proves the state without a GUI: `launchctl print gui/$UID/com.barbarian.syswatch` shows `state = running`, and `curl -s 127.0.0.1:8123/api/health` returns `ok:true`.

## Constraints
- **Never `sudo`.** Everything is in the user domain (`gui/$UID`).
- Do not touch `src/`, `dashboard/server.py` behaviour, `briefs/`, `GOAL.md`, `LEDGER.jsonl`, `tools/`.
- If the app cannot run headless (GUI-only), the **collector + dashboard** must still be fully launchd-managed — that is the part that must survive reboot.
- Do not add `launchctl submit`-style one-shot hacks; this is a durable agent.

## Acceptance commands (all must exit 0)
```
bash -n scripts/install.sh && bash -n scripts/uninstall.sh && echo SYNTAX_OK
bash scripts/install.sh
launchctl print gui/$UID/com.barbarian.syswatch | grep -E "state =|program =|runs ="
curl -s -m 5 http://127.0.0.1:8123/api/health | tee /tmp/t8_health.json | python3 -m json.tool
python3 -c "import json;d=json.load(open('/tmp/t8_health.json'));assert d['ok'] is True;print('HEALTH_OK',d['pid'])"
PID=$(python3 -c "import json;print(json.load(open('/tmp/t8_health.json'))['pid'])"); echo "pid=$PID"
date +%s > /tmp/t8_kill_ts; kill -9 $PID; sleep 25
NEWPID=$(curl -s -m 5 http://127.0.0.1:8123/api/health | python3 -c "import json,sys;print(json.load(sys.stdin)['pid'])")
echo "new_pid=$NEWPID (was $PID)"; test "$NEWPID" != "$PID" && echo RESTARTED
python3 -c "import time;print('recovered_in_s', int(time.time()) - int(open('/tmp/t8_kill_ts').read()))"
ls -la ~/Library/LaunchAgents/com.barbarian.syswatch* | head -3
git status --short packaging/ scripts/ | head -5
```
Do **not** reboot the machine yourself. If you believe a reboot is the only remaining proof, say so in the report and leave it to the supervisor — that is a decision, not an agent step.
