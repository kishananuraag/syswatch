# T12 — micro-fix: ioreg PATH blindness in launchd context

## Evidence (supervisor-verified, reproducible)

- Launchd service `/api/power` → `battery_w: None`, reason
  "voltage/current not exposed by battery API" — every call.
- Same second, standalone python → `battery_w: 4.09`, voltage 11581,
  amperage -356, pmset confirms discharging.
- Cause: `_ioreg_battery()` (dashboard/server.py ~line 352) runs
  `subprocess.check_output(["ioreg", ...])` by bare name. The launchd
  plist sets `PATH=/usr/local/bin:/usr/bin:/bin:/opt/homebrew/bin` —
  no `/usr/sbin`, so ioreg is not found inside the service and the
  function silently returns None. psutil (present in .venv) then
  supplies pct/charging, masking the failure down to the watts field.

## Fix

In `dashboard/server.py`, call ioreg by absolute path:
`["/usr/sbin/ioreg", "-n", "AppleSmartBattery", "-r", "-a"]`.
Nothing else changes. Do not touch 8123. Do not kill the launchd
dashboard. No new dependencies.

## Acceptance

1. `python3 -m py_compile dashboard/server.py`
2. With an empty-PATH environment proving the fix, standalone:
   `env PATH=/usr/local/bin:/usr/bin:/bin python3 -c "<read _read_battery_state>"` —
   battery_w must be a positive number (machine is discharging).
3. `launchctl kickstart -k gui/501/com.barbarian.syswatch.dashboard`, wait 5 s,
   then `curl -s http://127.0.0.1:8123/api/power` — `battery_w` must be a
   positive float, `unavailable_reason` null.
4. Report actual outputs. Do not claim success.
