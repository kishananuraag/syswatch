# T16A — The Instrument: one singular dashboard (IA redesign)

User verdict (2026-11-19 07:10): the skeleton is nice, but "the dashboard page
should be cool and singular, not like some 100 modules in the bar I have to
pick", the timeline "is in the corner and we need to implement where the user
loves to click", and elements with no meaning must go. Design reference:
iStat Menus dropdowns (the user's screenshots) — dials, colored value
hierarchy, dense but calm sensor rows.

Design contract: `docs/ui-design-system.md` (Parts 1 & 2) + inventory
`docs/machine-capability-inventory.md`.

## 1. IA: three views, one story

Nav becomes **Instrument · Apps · Analytics** (plus a small ⚙ gear that opens
a settings drawer with Permissions + about + the data sources table).

**Instrument** is THE dashboard: one continuous page, sections stacked,
scroll-told like a health monitor:
1. **Hero band** — six vitals with iStat-style hierarchy: CPU (value + small
   pressure dial), Memory (value + pressure), GPU util, Battery
   (`4:26 remaining · 38 % · 4.4 W draw`), Package power (`0.56 W · CPU 0.55
   · GPU 0.00 · ANE 0.00`, root-tier, live), Thermal (`Nominal` + temps when
   the SMC reader lands). Value big, unit small, delta chip, attribution.
2. **Time sections**: CPU (chart + P/E rings + per-core rows + consumers),
   Memory, GPU, Disk (speeds), Network, Power (timeline + coverage line),
   Battery, Thermal. Each section = chart + coverage footer + consumers panel.
3. Every module's data also reachable by scrolling — no tab hunting.

Keep hash routing (`#instrument`, `#apps`, `#analytics`, `#settings`).

## 2. The timeline moves to where hands go

- **Sticky, centered, under the hero band**: a segmented pill
  (`1m 5m 15m 1h 6h 1d 7d 30d 1y`), 32 px hit targets, active pill in the
  accent, sticky while scrolling sections. It is the ONLY range control.
- **Direct manipulation**: drag horizontally on any chart to zoom into that
  span (brush-select: range snaps to the nearest ladder step; double-click
  resets). This is the interaction humans love on timelines.

## 3. Wire the root data that exists NOW

`~/Library/Application Support/syswatch/root/sample.json` (fresh, verified):
`cpu_w 0.553 · gpu_w 0.003 · ane_w 0.000 · package_w 0.556 · thermal_pressure
"Nominal"`.

- GPU section gains a **Neural Engine** row: `ANE 0.00 W · util when present`.
- Power section: package/CPU/GPU/ANE W as live series + in the hero band.
- Thermal section: pressure level now; die temps arrive with the SMC reader
  (T16B) — render the slot with `needs SMC reader`, not a fake number.

## 4. Grant UX

After the macOS admin prompt returns, the panel must re-probe immediately
(2 s poll while the drawer is open) and flip to granted with a toast — the
user reports it "gets back to grant" for a while. The prompt itself takes
seconds; the UI must reflect reality the moment it changes.

## 5. Meaningless elements audit (user complaint, screenshot attached)

Go through EVERY rendered element and ask: does a human know what this means?
Delete or fix anything that: shows an unlabeled number, shows a label with no
value and no reason, duplicates another element, or renders a placeholder that
was never wired. In particular the Overview/CPU pages had a `—` percent chip
and stray metadata rows. Every number carries `unit · source · window`.

## 6. Honesty unchanged

`needs root` / `unavailable` + reason; no fabricated values; gaps as gaps.
