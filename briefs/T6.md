# T6 — The menu-bar app, built from scratch

## Goal
A native menu-bar app on this Mac, written by us, with no code, assets or UI copied from iStat Menus: one process, **< 15 MB RSS**, **< 1 % CPU at a 1 s refresh**, clean design, showing live metrics from the collector's own `--json` output. It survives the window being closed, restores on login later (T8), and never spawns a helper per sample.

## Non-negotiable: from scratch
- No decompiled iStat code, no copied assets, no pixel-copy of their layout. Their paid binary is the *reference for what to show*, never the source.
- Design language comes from this repo: `DESIGN.md` and `design_concepts/`. Read both first and say in your report which concept you followed.
- If a capability needs a private API (SMC temperature, fan RPM), it is an **optional module** that degrades gracefully — the app must run perfectly with zero sensors.

## Build order (this brief is one slice; do not gold-plate)
1. **Shell**: menu-bar item with a live CPU figure, dropdown showing CPU total, memory used/total, swap, top 5 processes by CPU, top 5 by energy (from T7B/T7C fields when present, otherwise omit the section).
2. **Data path**: read the collector **in-process** (preferred: call the library function that produces the JSON) or exec `syswatch --json` **once per second at most**, parse, and render. No polling faster than 1 s. No `ps`, no `top`, no `powermetrics`.
3. **Rendering discipline**: redraw only when a displayed value changes; a static screen must cost ~0 % CPU.
4. **Clean design**: one typographic scale, monospaced numerals, no gradients, no shadows, aligned right-edge values, IST for any timestamp. Dark and light both legible.

## Constraints
- Rust for the collector side stays as is; the app may be Swift/SwiftUI **or** the existing Rust tray — pick one and justify it in one paragraph (bundle size, RSS, build time).
- Exactly one process at idle. No launch agents beyond T8's.
- Do not touch `dashboard/`, `briefs/`, `GOAL.md`, `LEDGER.jsonl`, `tools/`, `scripts/`.
- No network access at runtime. No telemetry.

## Acceptance commands (all must exit 0)
```
cargo build --release 2>&1 | tail -3
ls -lh target/release/ | grep -E "syswatch|tray"
# launch it (headless-safe: must not require a GUI session to *start*)
(./target/release/syswatch-tray > /tmp/t6-tray.log 2>&1 &) ; sleep 8
pgrep -fl "syswatch-tray" | head -3
python3 - <<'PY'
import subprocess, statistics as st
pid = subprocess.check_output(["pgrep","-f","syswatch-tray"]).split()[0].decode()
rss, cpu = [], []
for _ in range(5):
    out = subprocess.check_output(["ps","-o","rss=,%cpu=","-p",pid]).decode().split()
    rss.append(int(out[0])); cpu.append(float(out[1]))
    import time; time.sleep(2)
mr, mc = st.mean(rss)/1024, st.mean(cpu)
print(f"tray rss {mr:.1f} MB  cpu {mc:.2f}%")
assert mr < 15.0, f"RSS above 15 MB: {mr:.1f}"
assert mc < 1.0, f"CPU above 1%: {mc:.2f}"
print("BUDGET_OK")
PY
# static screen must be ~free: second sample window
python3 - <<'PY'
```
