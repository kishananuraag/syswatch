## 3. The loop (this is the "auto-evolving" part)

**One iteration = one task. No task runs without a brief.**

1. **Read** `GOAL.md` + `BRAIN.md` + `LEDGER.jsonl` tail (what failed before, which model won)
2. **Pick** the next task from the backlog (dependency-ordered, smallest verifiable slice first)
3. **Brief** it (`briefs/<task>.md`): goal · exact file paths · constraints · **acceptance commands** · deliverable
4. **Dispatch** `opencode run "$(cat briefs/<task>.md)" --model <free-model> --format json` in a **git worktree**, log to `logs/<task>-<attempt>.log`
5. **Verify** — I run the acceptance commands myself. Exit code and output are the only truth
6. **Route the failure:**
   - fail 1 → same model, brief + **the failing output pasted in** (biggest success lever there is)
   - fail 2 → rotate model (next in the free list)
   - fail 3 → **no-progress detector**: don't retry, **re-plan the task** (split it smaller or the brief was wrong)
   - fail 4 → checkpoint to you with the log
7. **Record** to `LEDGER.jsonl`: task, model, attempt, duration, pass/fail, diffstat, failure signature
8. **Update** `BRAIN.md` (state, what works, pitfalls) — the loop's memory, so the next iteration starts warm
9. **Repeat** until goal met, or a stop condition fires

**Stop conditions:** all acceptance passes · three consecutive no-progress iterations · a task needs a decision only you can make (money, account, irreversible delete) · token budget for the day exceeded.

## 6. Mac-specific engineering notes (so the briefs are correct)

- **Sensors:** `sysinfo` does not expose Apple Silicon die temperature. `powermetrics --samplers smc` needs root → design: try `powermetrics`, fall back to `ioreg -r -d 1 -c AppleSmartBattery`/`IOHID` sensors, else report `unavailable` with reason. **Never fake a temperature.**
- **Service:** `windows-service` must be `#[cfg(windows)]`; macOS equivalent is a LaunchAgent, not a daemon — different lifecycle, needs `KeepAlive`.
- **Tray:** `tray-icon` handles macOS, but requires the main thread and an event loop (`tao`/`winit` or `tray-icon`'s own run loop). Agents get this wrong often → brief must state "menu bar item must be created on the main thread before the event loop runs".
- **Packaging:** unsigned binary is fine locally; Gatekeeper bites only on distribution. Say so in the brief so an agent doesn't waste an hour on codesigning.
- **Overhead:** measuring a monitor with a monitor is circular — use `ps -o %cpu=` in an external loop, not syswatch's own numbers.

## 8. Where it breaks (honest)

- **Free models and Rust:** borrow-checker fights are the classic failure. Mitigation: briefs specify "keep changes inside one function", and a compile error is fed back verbatim.
- **Tray/app work is GUI work** — the hardest thing to verify headlessly. If it can't be proven by a command, it goes to a **you-look-at-it checkpoint** with a screenshot, not to an agent's word.
- **`powermetrics` needs sudo** — either you approve a passwordless rule (`/etc/sudoers.d`) or sensors stay optional. Your call, not mine to assume.
- **Two clones is a live footgun** — T0 exists because if we skip it, agents will edit the wrong tree and we'll "lose" work that was never lost.
- **My verification is the real bottleneck.** If a task can't be expressed as a command, it doesn't get dispatched.
