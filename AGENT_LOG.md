### 2026-11-20 ~05:2x IST — T28 pairing protocol: code → X25519 → ChaCha20Poly1305 (DS4, verified in crates/net)
- `crates/net/src/pairing.rs` (new): `PairingSession` (Waiting→CodeGenerated→Connected→Paired, illegal transitions rejected, failure counter, `reset`), `start_pairing`/`start_pairing_local` → `(PairingCode, PairingHandle)`, `PairingHandle::wait_for_peer` (skips failed attempts, cap `MAX_PAIRING_ATTEMPTS = 5`, `CodeExpired` once the 5 min window closes) and `wait_for_peer_once` (single attempt, surfaces the reason), `accept_pairing`/`accept_pairing_local`, `PairedConnection` (`send`/`recv` on one bi-stream per message, `peer_node_id`, `endpoint`, `close`), `SessionCipher` (per-direction keys).
- Handshake: 4 flights on one bi-stream inside iroh's encrypted QUIC. Ring X25519 ephemerals (`ring::agreement`), transcript = SHA256("syswatch/pair/1" | SHA256(code) | id_d | id_l | d_eph | l_eph), each side signs `transcript|role` with its **ed25519 iroh identity**; HKDF-SHA256(salt=SHA256(code), info=transcript|direction) → `d2l`/`l2d`. Ephemeral rather than `SecretKey::shared()` static-static: forward secrecy + transcript binding. `chacha20poly1305` 0.10.1 (0.11 exists but drags aead 0.6 into an aead-0.5 tree), 12-byte random nonce per message, `Zeroizing` keys.
- `lib.rs`: `PairingCode` gained `addrs`/`relay_url` (serde default), `ticket()`/`parse()` (`syswatch1/<code>/<nodeid>/<addrs>/<relay>`, relay last so its `/`-es survive), `node_addr()`, `generate_with_ttl`, CSPRNG digits (was a hashed timestamp), `PAIRING_CODE_TTL_SECS`; `is_expired()` treats `expires_at == 0` as unknown (a received ticket carries no clock). `NetError`: `InvalidCode`, `CodeExpired`, `WrongCode`, `TooManyAttempts`, `Crypto`, `Protocol`, `TooLarge`.
- `endpoint.rs`: additive `bind_alpns`, `bind_local_alpns`, `connect_alpn`, `connect_addr_alpn` + a `LocalOnly` builder trait (loopback + no relay + no discovery in one place). `bind`/`bind_local`/`connect`/`connect_addr` keep their old signatures and behaviour — `connect_addr` hardcoded `ECHO_ALPN`, which silently broke every pairing dial until found.
- Verified in `crates/net`: `cargo build` clean (0 warnings), `cargo clippy --all-targets` 0 warnings, `cargo build --release` ok, `cargo test` **25 passed / 0 failed / 1 ignored in 2.19 s**, 3 consecutive runs identical. Root `cargo check` still exits 0 (root `Cargo.lock` re-resolved for chacha20poly1305/ring/zeroize).

- LEARNED: 1) A code-bound transcript makes a wrong code look like a bad *signature* on the dialer — it verifies flight 2 before it has any proof of its own. - Tests assert behaviour: real live-shaped payload parses field by field (+ `memory` alias preserved in `extra`); minimal payload → every number `None`; 7 malformed payloads rejected; round trip = device streams 3 ticks through `run()` and the viewer reads ticks 0,1,2 with the values the closure produced, then `session.close()` ends `run()` with an error; garbage frame → `BadSnapshot`, then a good frame still arrives on the same cipher; `send_once` = exactly one message (a 300 ms idle recv must time out); `run_until` = 5 ordered ticks then `Ok(())` on request; non-object snapshot refused *before* the wire (viewer receives nothing, stream kept alive during the check); viewer hang-up → `Err(NetError::Stream(_))`; `MetricStream`/`ViewerSession` are `Send + Sync`.
- Production-path proof (throwaway `examples/t29_live.rs`, deleted after the run): paired two loopback devices, streamed the **live** `/api/current` body from both servers through the encrypted channel, viewer read `cpu 18.9 % / ram 70.4 % / 8 cores / 452 procs / 5 ifaces / 17 temps` from the Rust agent body (6465 B, 20 keys) and `cpu 18.4 % / ram 77.3 % / 468 procs / 0 temps` from the psutil body (4800 B, 17 keys), `extra` carrying `["memory"]`; the device stream then ended with `stream error: closed by peer: paired session closed (code 0)`.
- LEARNED: 1) `Box<dyn Fn() -> Value + Send>` is not `Sync`, so any `&self`-borrowing async method is not `Send` and `tokio::spawn(stream.run())` refuses to compile; keeping the brief's constructor signature and putting the closure behind a `std::sync::Mutex` (never held across an await) makes the type `Sync` for one uncontended lock per tick — cheaper than widening the public signature to `+ Sync` and forcing every caller's closure to be `Sync`. 2) Dropping a `PairedConnection` tears down the endpoint, so "nothing was sent" is only provable while the sender is alive: a test that drops the stream before checking the idle channel sees a *closed-channel error*, not a timeout, and reads as a false failure. 3) The two `/api/current` implementations already diverge (`available_bytes` only on the Rust side, `power`/`agent`/`collector` extras, `ts` with `Z` vs `+00:00`, psutil's `temps_c` empty without root) — typing only the blocks a UI binds and keeping the rest verbatim is what lets one viewer consume both without a translation layer, and is why the tolerance rules (float-for-int, null→None) are in the parse path rather than in a per-source adapter.
