# SysWatch — contract

## 1. What it is

A machine-watch agent: a Rust agent with a dashboard that reports CPU, memory and process health. The build goal is a stated CPU budget at a stated poll interval, proven by measurement, not by opinion.

## 2. Sources of truth (ranked — higher wins, lower gets fixed)

1. `ACCEPTANCE.md` — the numbered tests (A-series). Its own rule: a dimension is green only when its commands exit 0 and the numbers are pasted.
2. `GOAL.md` — the target numbers (budget and poll interval).
3. `BRAIN.md` and `AGENT_LOG.md` — doctrine and the running record.
4. The `before_*.csv` and `after_*.csv` files — the measurements. A claim without a row here is a guess.

## 3. Acceptance commands

**The tests live in `ACCEPTANCE.md`. Run them. Do not write new ones.**

| Test | Command | Pass value |
|---|---|---|
| Install from a fresh shell | `bash scripts/install.sh` | exit 0, and the binary runs after a new shell |
| CPU budget | the benchmark block in `ACCEPTANCE.md` | the printed number is below the budget in `GOAL.md` |
| Regression set | `python3 -m pytest -q` if a `tests/` dir exists | exit 0 |
| **UI renders** (any round touching `dashboard/static/*`) | load `http://127.0.0.1:8199/` and assert `document.querySelectorAll('#tilegrid .tile').length > 0` | count > 0, and no view is empty |
| **UI behaves** | click a tile → `is-focused` 1 / `is-dimmed` n-1; Escape → 0/0; customize → untick a tile, reload | the hidden tile stays hidden and `localStorage['syswatch-tile-config']` carries it |

A dimension is done only when its command exits 0 and the number is pasted into the report.
`node --check` and `grep -c` are syntax and text checks — they passed on a dashboard that rendered zero
tiles. Anything that can fail at runtime needs a runtime check, i.e. a browser assertion on element
counts, not on source text.
