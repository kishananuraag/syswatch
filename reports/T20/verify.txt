4. Known gaps (measured, not guessed)
=============================================================
a) The server process that serves :8123 (PID 50217, LaunchAgent
   com.barbarian.syswatch.dashboard) is still the PRE-T20 code:

   $ curl -s "http://127.0.0.1:8123/api/power/history?range=1h" | ...
   sampling_s: 5.0 | powermetrics block: None | coverage_text: sampling every 5 s · 61 samples
   points: 61 | points carrying cpu_temp_c: 0

   The static files it serves are the new ones (read from disk per request), so
   the new UI is live but the ring behind it is still 5 s with no temperatures.
   Loading the server-side half needs one restart — NOT done here, because
   `pkill -f dashboard/server.py` is forbidden:

       launchctl kickstart -k gui/$(id -u)/com.barbarian.syswatch.dashboard

b) The installed root daemon is still the pre-T19 shell sampler at 5 s:

   $ ps -Ao pid=,ppid=,command= | grep power_sampler
   65591     1 /bin/sh /usr/local/libexec/syswatch/power_sampler.sh 5000 …
   81778 65591 /bin/sh /usr/local/libexec/syswatch/power_sampler.sh 5000 …
   81779 81778 /usr/bin/powermetrics -n 1 -i 5000 -f text -s thermal

   /Library/LaunchDaemons/com.barbarian.syswatch.power.plist runs
   power_sampler.sh, not syswatch-powerd. The repo now ships 15 s
   (powerd default + plist template + `powermetrics.interval_ms`), but the
   machine keeps sampling at 5 s until the grant flow installs T19/T20 — that
   needs the admin prompt, so it is Kishan's call, not mine.

c) `tools/verify_T20.sh` does not exist in this repo (tools/ has t5, t7c, t8,
   t10, t11). Nothing under tools/ was created or edited.

d) The thermal ring restarted with this run, so its chart starts empty and
   fills at 15 s. The empty state is the honest one: 1 °C sample = 0 % coverage,
   never a flat line.
